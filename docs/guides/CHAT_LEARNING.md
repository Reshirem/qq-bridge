# 黑话记录与表情包学习

## 功能思路

这两个模块独立实现，参考 MaiBot 的原文证据、来源范围、含义推断和情绪标签，以及 qq-bridge 历史版本的候选/确认/拒绝流程。没有恢复旧版学习器、旧 preset 或逐 QQ 的 DSH 会话架构，也不学习或修改角色说话风格。

新收到的消息进入有界的后台队列。学习器每次选取同一 QQ 来源的一批消息，在独立的 DSH headless 进程中分析。模型输出结构化建议，桥接核对证据编号、原文和图片编号后，原子保存知识并移除已处理消息。它不向 QQ 发消息，也不操作主角色会话。

主角色读取历史/未读消息时，响应会附带原文命中的可用黑话。`qq_slang_query` 支持按当前来源主动查询。`qq_list_stickers` 在同一个表情记忆库中检索已启用的来源，返回的标识可直接用于看图与发送。

## 使用

更新代码后用 `start.bat` 重启 qq-bridge，或先运行 `scripts/a-memorix.ps1 start` 再启动桥接。重新连接 DSH 的 QQ MCP 或重启 DSH，以载入复检工具和新的聊天提示。

控制台的「学习与素材」包含以下页面。

- **后台学习**：开关、学习范围、批量阈值、冷却时间、最长等待、立即处理一批、队列/错误与累计 token。配置保存后立即生效，并取消正在使用旧配置的批次。
- **黑话记录**：搜索、按来源和状态筛选、手工新增、编辑、删除与原文证据。`candidate` 表示含义不足以采用；`learned` 表示模型给出了含义且置信度至少 0.85，仍是推断；`confirmed` 表示人工确认；`rejected` 不再被自动更新。确认后的解释和用法不会被学习结果覆盖，但可以追加证据。
- **聊天表情**提供「允许角色使用普通表情」开关，控制从聊天学到的表情与 QQ 账号收藏。这里也可以编辑本地注解、同步收藏、处理角色提出的修正。
- **商城表情**提供「允许角色使用商城表情」开关，控制手动收录的商城包。两个开关可以分别保存，立即影响角色的检索、看图、修正建议与发送。只想让角色用商城包时，关闭普通表情、开启商城表情即可。关闭任一来源仍可在 WebUI 管理已有素材。

配置项为 `socialV2.sticker.regularEnabled` 与 `marketEnabled`，新部署默认均开启。旧配置中单个 `sticker.enabled` 的值会应用到两类来源。聊天表情的后台学习仍由 `chatLearning.stickers` 单独控制。

本地表情自动学习只处理 QQ 标记为表情的 `sticker`、带 `emojiId` 的商城表情或 `subType=1` 图片，不扫描普通照片、文件或合并转发。兼容 SnowLuma 将商城表情作为 `sub_type=0` 图片发送的情况。模型看图后再次判断是否为可复用表情。GIF 使用已有 FFmpeg 归一化链路生成抽帧拼图供学习，保存和发送仍使用原始字节。未成功把图片提供给模型时，不接受表情描述。

后台学习开关独立于主角色的休息、睡眠和 WebUI 停止。需要停止分析时关闭“启用后台学习”；已有记录仍可检索与使用，待处理队列保留。来源范围变窄后，范围外的待处理消息不会运行；重新包含该来源后可继续处理。当前只学习启用期间新收到的消息和已经保存的待处理队列，不回溯旧 QQ 数据库或历史 DSH 会话。

## 聊天时选图与复检

角色在普通聊天里自行选择用文字、用一张图完整作答，或把表情放在几条文字的前、中、后。没有发送频率要求。想用图时，调用 `qq_list_stickers(key, query)`，用自然语言描述想表达的意思，再把候选的稳定 `id` 原样交给 `qq_send_sticker`。模糊时可先用 `qq_get_sticker_image` 看原图，也可以换图或放弃。

角色检索依赖本机 A_Memorix。启动脚本为表情单独创建 `qq-bridge-stickers` 和专用密钥。桥接把已启用条目的描述、标签、用法编入这个空间，保存索引记录与可发送表情的对应关系。每 30 秒最多同步 16 个索引变更。图片保存在本地文件或 QQ 收藏。

`query` 必填，例如“有点尴尬，想轻松地缓和气氛”。角色每次最多收到 5 个候选，每项只有可发送的 `id` 和描述。桥接按检索排名核对当前会话可用的表情。没有命中时返回空列表，服务不可用时返回检索错误。管理员可以在 WebUI 浏览和维护完整目录。角色长期记忆整理跳过表情候选查询，实际收发的表情仍有聊天或发送回执作为证据。

角色看图后可选用 `qq_suggest_sticker_edit` 提出描述或标签修正，同一条目同时只保留一份待确认建议。控制台「聊天表情 → 角色的修正建议」显示原图和前后对照。采纳本地表情建议会将该条目标为人工确认，采纳 QQ 收藏建议会更新桥接本地检索资料。忽略建议即结束这次复检。资料已变化、条目已停用或删除时，旧建议无法覆盖新内容。

## 手动管理商城表情

打开「学习与素材 → 商城表情」。输入包名可以查找当前账号在本机 QQ 留过资源的包、桥接本次运行收到过的包和已收录的包。已有本地商城包归档的文件名也可提供包 ID。首次按名称查找会从腾讯读取这些编号对应的目录。要添加本机没见过的包，可直接粘贴手机 QQ 的商城详情链接或数字包 ID。

点开包可以预览每张表情、原名和商城关键词。「收录整包」保存原图，并排队调用当前学习模型分析这一套。模型在独立会话中收到整包原名、原关键词和编号，每页查看四张图，对照全套画面后逐张解释语气和用法。桥接核对已读页及返回的编号，全部齐全才保存。模型用量归入「后台学习」。

新包从商城原释义开始提供检索，完成分析后逐张更新同一个表情记忆空间。商城原名和原关键词随注解入索引。收录后，包详情会显示排队、分析中或完成状态。失败原因显示在「移除整包」一行下方，点旁边的「重试整包分析」可再次运行。已收录但尚无分析记录的旧包可点「分析整包」。重新分析保留人工修改的注解和标签，桥接重启后恢复已排队或中断的整包任务。关闭后台学习里的「学习表情包」只影响从聊天自动学习；手动收录商城包仍会触发整包分析。移除整包也会移除该包的注解。

角色沿用现有的意图检索、看图和发送工具。手动收录的表情适用于所有来源，索引按现有同步周期更新。桥接通过 QQ 图片消息发送这些本地素材。

## 配置与资源限制

`config.example.json` 的 `chatLearning` 是模板；已有安装未填写该段时使用以下默认值。学习器复用 `dsh.provider`、`dsh.model`、`dsh.reasoningEffort` 和已有的 DSH CLI 发现逻辑（`memoryOrganizer.cliPath` / `DSH_CLI_PATH`）。自定义 Provider 从 Desktop profile 复制所选模型的连接定义，通过 DSH 凭据引用取得密钥，不把密钥写进学习任务。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` / `slang` / `stickers` | `true` | 总开关 / 黑话 / 表情学习 |
| `sources` | `[]` | 学习来源；空数组表示所有收到消息的来源 |
| `minMessages` | `20` | 同一来源触发批次的消息数 |
| `batchSize` | `30` | 单批最多消息数 |
| `cooldownMs` | `300000` | 全部来源共用的最短启动间隔 |
| `maxWaitMs` | `900000` | 消息不足一批时的最长等待 |
| `maxImages` | `3` | 每批最多图片数，达到预算时将余下消息留给后续批次 |

队列每 30 秒检查一次，空队列不调用模型。每次最多运行一个学习进程，5 分钟超时。失败保留原消息，并从至少 5 分钟开始退避，最长 30 分钟。同一消息连续失败 3 次后暂停自动重试。「立即处理一批」优先处理当前学习范围内暂停的消息，新消息仍可自动学习。黑话的引用须指向本批原文，引用 QQ 消息 ID 时，桥接核对其唯一对应的消息并保存完整证据编号。修改或关闭设置时取消的批次保留在队列中。

后台学习最多保留 1000 条待处理消息、3000 个近期去重编号、2000 个黑话条目和 300 个聊天表情。手动收录的商城包独立计数。黑话最多保留 20 条原文证据。队列满时丢弃最早的待处理消息并显示累计数量。知识库满时明确失败。消息正文每条最多 1500 字符。图片沿用媒体字节和像素限制，单个本地文件最多 8 MiB，未采用的图片由后台清理。

学习会产生额外模型用量。「后台学习」保留 DSH 上报的累计输入与输出。「令牌与花费」按功能归集有上报的学习步骤，包含批次失败前已产生的用量。升级前只有累计值的学习历史保留 token 数量。学习进程关闭自动生成会话标题，避免每批额外调用一次模型。

## 来源与持久化

- 自动条目默认归属 `group:群号` 或 `private:QQ号`。模型不能改变归属或把条目升级为全局。
- 管理员可以明确改为 `global`。主角色查询只返回目标来源和 global 的可用记录，不返回其他来源的证据。
- 这层筛选约束知识工具的结果；主角色本身仍共用全局上下文，不能宣称实现了所有 QQ 内容的程序级隔离。
- `state/chat-learning.json` 保存队列、学习结果、状态和用量；`state/learned-stickers/<sha256>.bin` 保存原始表情。使用内容哈希去重，读取同时校验真实路径与文件摘要。
- 首次使用新库时，若存在旧 `state/slang.json`，只读取并转入新库；旧文件不修改。旧记录标记为 `unassigned`，保留旧证据供管理端查看，在管理员确定来源之前不提供给角色。导入结果在第一次实际写入时持久化。损坏的旧文件或新库均导致学习模块停用，其他桥接能力继续工作，不把损坏库当空库覆盖。
- 管理端编辑与学习完成采用同一个存储模块；学习期间人工确认/拒绝会在提交时被尊重。入队、学习结果与队列消费均先成功写盘再替换内存状态。

## 工具与接口

`/api/learning/*`、`/api/slang*` 是控制台管理接口，agent token 无权访问。`/api/socialV2/slang-query` 沿用既有内部凭证和全局会话绑定；学习器不能调用它。

headless 每批只挂载 `mcp-learning-images.js`，清单由桥接产生，工具没有路径、URL、QQ 目标或写入参数。`learning-tool-guard.mjs` 在执行前只允许 `mcp__qq-learning-images__learning_images`，其他工具即使被用户 headless profile 额外挂载也被拒绝。模型最终输出不能触发文件路径访问或 QQ 操作。

本地表情发送复用原有 `sendStickerV2` 和 HTTP 出站入口：同样校验会话、目标并记录审计，并在发送队列等待后再次检查表情的来源与启用状态。图片字节由桥接读取，以 base64 提交给 OneBot。

```text
npm run test:learning
node scripts/test-audit.mjs
npm run test:console-ui
node scripts/test-learning-dsh.mjs
```

前三项使用隔离数据/假网关；浏览器测试需要已有 Playwright，可用 `PLAYWRIGHT_MODULE` 指向安装目录。最后一项是可选的 Windows DSH Desktop 接入测试：使用临时 DSH_HOME 和回环假模型，实际验证 headless 加载、工具守卫、图片 MCP 与完成事件，不调用真实模型或 QQ，也不读写生产会话。
