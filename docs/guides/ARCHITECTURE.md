# 运行架构与渐进式重构

## 当前方向

项目使用一个持久的全局 `desktop-agent` DSH 会话，定位为可自主活动的长期陪伴者。WebUI 是启动、查看和引导会话的主要入口；电脑操作、QQ 和记忆是可按需使用的能力、渠道与空间。群号和 QQ 号只标识消息来源与发送目标，不定义 DSH 会话或独立 agent。

## 身份与项目用词

- 项目定位是 DSH 自主陪伴运行时；`qq-bridge` 是仓库名，SnowLuma/QQ 是按需消息集成。文档和界面优先描述全局会话与自主活动，再说明具体渠道和工具。
- 固定前缀规定长期会话、自主探索和工具协作方式；当前选中的人格卡定义具体身份、形态、性格与表达方式，可以是人类、动物、幻想角色或其他非人设定。没有选中人格卡时，使用通用的自主陪伴者定位，不默认指定物种或形态。
- 电脑是陪伴者可探索和使用的活动空间之一。QQ 是可按需读取和操作的消息渠道；WebUI 是控制入口。它们描述能力和入口，不限制人格卡设定。
- `desktop-agent`、`desktopAgent`、`state/desktop-agent.json` 和 `/api/console/desktop-agent` 是现有技术 ID、状态文件与路由名，保留以兼容 DSH 和持久数据。新增用户界面和文档文案优先使用“陪伴者”或“全局陪伴者会话”；需要说明能力时写“电脑操作”“QQ 消息渠道”等具体名称。
- 调整身份口径时，同时检查固定前缀、preset 展示名、WebUI 文案、README 和 DSH 安装指南，避免把技术 ID 误写成固定的人格类型。

继续按明确职责渐进式整理 `src/bridge.js`，不需要为了代码体量整体重写。每次改动先找出状态所有者、持久化格式、调用方和安全门，再以小步迁移保持行为可审查。

## 当前运行行为

- SnowLuma 提供 OneBot 事件流。桥接按 QQ 来源缓存收到的消息；普通群消息正文不会自动进入模型上下文。
- 私聊、真正发给机器人的原生 @、已验证的回复/引用和配置的 `socialV2.attentionKeywords` 命中会向同一全局会话发送元数据提醒。提醒不含正文，也不强迫陪伴者读取或响应。
- 全局陪伴者使用 `mcp-snowluma-safe.js` 当前注册的完整 QQ 工具集，可按需枚举群/好友、读取消息及主动发送。MCP 自动从 `state/desktop-agent.json` 读取桥接内部凭证并附加到请求，模型不用处理令牌；不会检查发起调用的 DSH session，MCP profile 中可用该工具的会话共享相同权限。桥接用全局自主运行时状态校验凭证，发送仍检查全局活动回合并执行限频与审计。直接通过 QQ 桌面 UI 发送不经过桥接 API 门禁。
- 可选 A_Memorix 记忆由 `a-memorix-gateway.js` 统一接入；DSH 工具、首次会话摘要和 WebUI 管理 API 都经过它访问同一 namespace。DSH 工具继续经受活动回合与 agent token 校验；调用参数中的记忆正文和搜索词不会进入工具参数日志。桥接不直接读写记忆服务文件。设计和部署前提见 [MEMORY_ARCHITECTURE.md](MEMORY_ARCHITECTURE.md)。
- `dsh-computer-use-win` 提供本机桌面操作能力。用户开始使用电脑时，陪伴者应让出界面控制权；ChatGPT、DSH、qq-bridge 和 SnowLuma 的 GUI 在无关任务期间保持受保护。详情见 [RULES.md](../../RULES.md)。
- 全局会话生命周期为 `idle`、`active`、`resting`、`recovering` 和 `stopped`。活动回合最后调用 `agent_rest`；有限休息为 1 秒至 12 小时，到期后恢复一轮；用户在 DSH 对话中发消息、提交 WebUI 任务或收到有效 QQ 提醒，都可提前结束有限或无限休息。休息期间异常回合的指数恢复重试暂停。
- 如果活动回合刚通过 QQ 回复某个来源，陪伴者会在休息前用最近一次 `readThroughSeq` 检查该来源是否有新未读；桥接会清掉已被读取水位覆盖的排队提醒，只保留尚未展示的新提醒，避免同一消息重复唤醒。
- 回合没有调用 `agent_rest` 就结束时，桥接按 1、2、4、8、16 分钟尝试恢复，之后间隔最长 30 分钟。WebUI 停止会取消当前和排队中的 DSH 工作并持久进入 `stopped`；只有 WebUI 手动启动或提交任务才解除停止态。
- 桥接不运行周期性模型心跳，也不靠无目的的长等待工具维持在线。`qq_wait_for_messages` 可用于活动回合内等待某个具体相关交流。
- `state/desktop-agent.json` 保存全局会话 ID、令牌和生命周期。旧的逐 QQ 会话映射、映射令牌、映射控制接口和 `qq-chat-v2` preset 已从当前代码与 bundle 移除。历史 DSH 会话由 DSH 自行保留，桥接不再枚举、修改或归档它们。
- 读取本地 NTQQ 数据库仍是延期的技术尝试。当前消息来源仍是 SnowLuma；不要自行开始数据库读取实验，等用户再次提出后再评估。

当前权限约定见 [RULES.md](../../RULES.md)，安装过程见 [DSH_SETUP.md](DSH_SETUP.md)。长期记忆目标与实施边界见 [MEMORY_ARCHITECTURE.md](MEMORY_ARCHITECTURE.md)。

## 当前代码边界

`src/bridge.js` 仍是组合与协调中心，涵盖启动配置、OneBot 事件、全局 DSH 生命周期、QQ 消息缓存、WebUI HTTP 路由和发送策略。共享状态较多，所以优先从可独立定义输入输出的职责开始拆分。

已有边界包括：

- `src/autonomy-policy.js`：纯函数形式的 QQ 注意信号分类。
- `src/dsh-client.js`：DSH API、鉴权和事件流客户端。
- `src/mcp-snowluma-safe.js`：SnowLuma QQ 工具和桥接 API 的调用端。
- `src/mcp-host-server.js`：只读的主机/SnowLuma 状态工具。
- 媒体、角色卡、网络抓取、敏感内容和 token 账本等独立模块。

## 渐进式重构顺序

把以下职责作为可逐步明确的边界，不强制采用固定目录结构：

1. **运行时组合**：启动、依赖接线与关闭流程。
2. **QQ 网关**：OneBot 事件归一化、消息缓存和 QQ 出站传输。
3. **全局会话管理**：唯一 `desktop-agent` 会话的创建、恢复、停止与状态持久化。
4. **自主调度**：休息、异常恢复、注意信号与活动回合协调。
5. **QQ 消息存储**：按来源索引、去重、水位和按需读取；与将来的数据库适配器保持小接口。
6. **控制台 API**：将管理路由与会话、消息和发送策略解耦。
7. **动作策略**：集中说明 SnowLuma 发送的授权、限频和审计边界，并保留用户允许的桌面控制能力。

## 改动原则

- 一次处理一个具体职责，先确认它读写的状态与所有调用方。
- 抽取时传入窄依赖，避免模块反向依赖桥接入口形成隐式全局耦合。
- 结构整理应保持既有行为；有意改变行为时，同步更新 RULES、文档、控制台和持久状态迁移。
- 不要把 QQ 消息正文或关键词信号自动塞进全局模型上下文。活动检测和模型观察是两件事。
- 不要在清理中重新引入逐群/逐私聊 DSH 会话、逐来源 agent 令牌或并行运行时。
- 发送授权检查应保持集中，覆盖桥接 API 发送；桌面 GUI 发送的限制另见当前用户授权与 [RULES.md](../../RULES.md)。
- 用户已将直接 QQ 数据库读取列为延期实验；只有用户重新提出后再开展。

## 何时考虑整体重构

只有当单一全局会话的具体功能无法通过小步整理实现，或共享状态让迁移风险不可接受时，才重新评估更大规模重构。先明确可验证的边界、迁移方案和失败回退，再决定是否更换整体结构。
