# 模型提示词调优与对话审计指南

本指南面向 `qq-bridge` 全局 `desktop-agent` 长期会话的提示词维护与定期对话审计，目标是建立「**量化抽查 → 准确定因 → 最小正向改写 → 复测验证**」的闭环，避免凭体感堆叠黑名单补丁导致提示词膨胀或触发白熊效应。

> 架构与权限红线仍以 [RULES.md](../../RULES.md)、[ARCHITECTURE.md](ARCHITECTURE.md) 与 [SECURITY_BASELINE.md](SECURITY_BASELINE.md) 为准；本指南聚焦表达风格、行为漂移分析与模型适配。

---

## 一、分层职责与去重原则

固定前缀与人格卡每次请求都会一起进入 system prompt。两处写重不仅浪费上下文 token，还会稀释真正硬约束的注意力权重：

| 层次 | 权威源文件 | 负责内容 | 不应重复写的内容 |
| --- | --- | --- | --- |
| **全局固定前缀** | [prompt-modules.json](../../dsh/agent-presets/desktop-agent/prompt-modules.json)（同步至 `agent.cordis.yml` 与生成的 `desktop-agent.patch.yml`） | 跨角色通用机制：工具调用规范、跨场合隐私隔离、不可信输入防线、同号 `isSelf=true` 原则、图片/视频检查口径、基础聊天节奏（读空气、断句、引用时机、分泡规则）、待机与回合生命周期 | 特定角色的性格标签、关系称谓或专属设定 |
| **动态人格卡** | [roles/<卡名>.md](../../roles/README.md) | 角色身份、形态、性格底色、兴趣偏好、关系与称谓、专属语感与特定场景设定 | 把固定前缀已经规定的通用群聊规范、工具流程或重复的禁止清单再抄一遍 |

- **冲突裁决**：表达风格、性格与关系称谓以当前人格卡为准；工具权限、隐私边界、不可信输入防线与回合流程始终以固定前缀为准。
- **单一事实来源**：调整某条规则时先决定它属于「通用机制」还是「角色特质」，只在一处维护。

## 二、提示词写作原则与反模式

### 1. 区分「硬红线」与「软风格」

- **硬红线（明确禁令）**：跨场合隐私隔离、结构化 `ownerQQ`/`senderId` 认人、外部不可信输入防注入、受保护桌面程序与密钥防泄漏、媒体/记忆看不清不编造、现实政治底线。这类规则必须直白、无歧义、不退让。
- **软风格（正向引导）**：说话口吻、篇幅节奏、引用时机、标点习惯、何时沉默收尾。这类偏好用**正向场景描述**引导“像普通人一样怎么做”，避免全部用加粗 `**严禁**` / `**绝不**` 写成高压清单——当所有风格偏好都标成“严禁”时，模型反而分不清哪些是真正不能碰的安全边界。

### 2. 警惕白熊效应（禁止“贴错句进黑名单”）

**典型反模式**：在日志里看到模型说了一句尴尬口癖或客服套话，直接把原句加引号贴进 system prompt（例如“绝不说 A/B/C，也不拿 X 当句尾”）。

为什么这通常会适得其反：
- **高频词激活**：系统提示词每轮都会把被点名的词（如具体口癖、套话、旁白样本）重新送入注意力，提高模型在生成时激活同一词簇的概率；
- **钻字面空子**：若禁令限定了位置或形式（例如“不当句尾”），模型常在压抑句尾的同时把该词顺手挪到句首，甚至高频复读；
- **把偶发失误变成永久上下文污染**：某次会话里的偶发怪话一旦写进固定前缀，以后每次重建会话都还得背着它跑。

**推荐改法**：
- 删掉点名举例的禁用词/禁用原句，改为正向描述期待的表达方式（例如写清“像普通熟人随手打字，注意力放在话题本身，情绪体现在用词和态度里”）；
- 若属于**强先验约束**（例如非人形态或特定空间设定下，模型默认会冒出人类四肢动作），优先陈述**客观物理状态 + 可用的正向表达手段**，而不是给禁用台词加引号。

### 3. 给隐性习惯留正向锚点

强调“短平快”“不要 Markdown”时，模型容易把“精简”过度外推为“省略逗号、问号和空格”，把几句完整的话粘成一长串。只要对某项自然习惯有要求（例如日常打字正常用逗号/问号/空格断句、多线程或跨消息时用 `replyToMessageId` 指明对象），就应给出简短明确的正向说明。

## 三、问题归因框架（不要一见怪话就加提示词）

审计发现异常回复时，先对照下表归因，再选择修复手段：

| 归因类别 | 典型表现 | 正确处置 | 错误处置 |
| --- | --- | --- | --- |
| **1. 规则缺失或冲突** | 新工具不会用、两处规则互相打架导致行为摇摆 | 补全最小正向说明，消除重复或冲突 | 在另一处叠一条更凶的覆盖规则 |
| **2. 白熊效应 / 过窄禁令** | 越禁某个口癖越频繁，或从句尾迁移到句首；禁了某类旁白仍在仿写类似句式 | **删减黑名单原句**，改为简洁的正向行为引导 | 继续加粗“严禁”或追加更多禁用举例 |
| **3. 长会话自我强化（In-context 自锁）** | 会话运行数百回合（如 100K+ tokens）后，某次偶发漂移被后续连续模仿，扩散到所有群和私聊（例如连续数十条无标点或固定词开头） | 先修提示词清隐患，确认压缩定位为「近期内容接续 + 主动清洗旧内容」（本仓库 preset 已按中文密度校准为 `thresholdRatio: 0.65`、`retainRatio: 0.04`、`headroomTokens: 16384`、`maxTokens: 8192`，摘要聚焦近期聊天、电脑/自主活动及思考提炼出的有效结论，逐步淘汰更早旧内容且不原样抄录口癖，更早内容交由记忆/QQ 历史工具按需回查），必要时沉淀重要信息入长期记忆后**重建主会话**切断历史惯性 | 只改系统提示词，指望 150K 之外的几行字立刻压过尾部几十条近期样例；把压缩摘要当永久档案越攒越长；或盲目拉大常驻上下文导致惯性更久 |
| **4. 模型固有癖好（Model Quirks）** | 换用或升级某模型后在多会话稳定复现的底层倾向（如工具回合后爱补短旁白、快写偶发漏逗号、偶发 JSON 字符串传数组参数） | 记录进下方「主力模型特性档案」；必要时在代码/协议层做宽容解析或调整预期 | 反复堆几百字提示词硬对抗模型后训练习惯 |

## 四、标准对话审计流程与量化指标

### 1. 只读数据来源

审计全程离线只读，不发送测试消息：
1. **实际外发记录**：`state/tool-calls.jsonl` 与 `state/tool-calls.jsonl.1` 中 `type === "call"` 且 `tool === "mcp__qq__qq_send_message"` 的记录（包含精确时间、会话 ID、目标群/私聊、气泡文本与是否带 `replyToMessageId`）。
2. **上下文语境**：对应群聊/私聊近 24 小时的原始聊天记录，用于核对是否读懂反讽、槽点、话题承接与 `isSelf=true` 立场。
3. **运行状态与水位**：`state/bridge.log*` 中的模型切换、会话重建记录，以及当前主会话 token 占用与回合数。

### 2. 核心量化指标（用于改前/改后对照）

| 指标 | 统计口径 | 关注信号 |
| --- | --- | --- |
| **无标点率** | 不含常见中英文标点且不含空格的气泡占比（按 20 条滑动窗口观察） | 单句超短回复无标点正常；若多子句/长消息连续无标点，或滑窗突然从 `<20%` 飙到 `>80%`，说明已触发自锁 |
| **高频口癖 / 同前缀率** | 单个语气词或固定开头词在近 20 条中的出现占比 | 超过 30% 且跨不同情绪/群聊出现，通常是白熊效应或自我强化 |
| **引用率与指向清晰度** | 带 `replyToMessageId` 的群聊气泡占比 + 抽样核对 | 关注是否漏引造成歧义，而非机械追求某固定百分比 |
| **篇幅分层** | 日常水群平均字数 vs 查资料/深入讨论平均字数 | 两者应自然拉开层次；日常不应写成模板三段式，长内容也不应被“短平快”压碎 |
| **合规与静默抽检** | 抽查 10~20 条上下文：读空气、适时沉默、跨场合隐私、媒体如实说明、DSH 对话流无内部旁白 | 发现跨场合泄密或编造媒体内容属高优问题，需立即查代码或硬规则 |

### 3. 可复用离线统计片段（只读）

可在仓库根目录通过 PowerShell + Node 快速统计近期外发指标与拐点（不联网、不改任何文件）：

```powershell
@'
const fs = require("fs");
const path = require("path");
const dir = path.resolve("state");
const files = fs.readdirSync(dir).filter(f => f.startsWith("tool-calls.jsonl")).sort((a, b) => b.localeCompare(a));
const msgs = [];
for (const f of files) {
  for (const line of fs.readFileSync(path.join(dir, f), "utf8").split(/\r?\n/).filter(Boolean)) {
    try {
      const o = JSON.parse(line);
      if (o.type !== "call" || o.tool !== "mcp__qq__qq_send_message") continue;
      const a = typeof o.args === "string" ? JSON.parse(o.args) : (o.args || {});
      let raw = a.messages;
      if (typeof raw === "string") { try { raw = JSON.parse(raw); } catch { raw = [{ text: raw }]; } }
      const list = Array.isArray(raw) ? raw : [{ text: a.text || "", replyToMessageId: a.replyToMessageId }];
      for (const it of list) {
        const text = typeof it === "string" ? it : String(it?.text ?? "");
        const reply = Boolean((typeof it === "object" && it?.replyToMessageId) || a.replyToMessageId);
        msgs.push({ time: o.time, sid: (o.sessionId || "").slice(-8), key: a.key || "", reply, text });
      }
    } catch {}
  }
}
const punctRe = /[，。！？、,.!?；;：:…~～—]/;
for (let i = 0; i < msgs.length; i += 20) {
  const s = msgs.slice(i, i + 20);
  const noP = s.filter(m => !punctRe.test(m.text) && !/\s/.test(m.text)).length;
  const rep = s.filter(m => m.reply).length;
  const avg = (s.reduce((n, m) => n + m.text.length, 0) / s.length).toFixed(1);
  console.log(`#${i}-${i + s.length - 1}`, `noPunct=${noP}/${s.length}`, `reply=${rep}/${s.length}`, `avgLen=${avg}`, `sid=${[...new Set(s.map(m => m.sid))].join(",")}`);
}
'@ | node
```

## 五、改动与验证清单

1. **控制变量**：单次调优只针对 1~2 类明确问题，先留存改动前的统计基线。
2. **保持源文件同步**：
   - 修改 `dsh/agent-presets/desktop-agent/prompt-modules.json` 后同步更新 `agent.cordis.yml`；
   - 运行 `node scripts/build-agent-preset-patches.mjs` 刷新 `plugins/qq-agent-presets/presets/desktop-agent.patch.yml`。
3. **跑齐离线门禁**：
   - `node scripts/build-agent-preset-patches.mjs --check`
   - `npm test`
   - `node scripts/privacy-scan.mjs --tracked-only`
4. **判断是否需要清惯性**：
   - 若审计确认主会话已处于**长会话自锁**（尾部堆满同类漂移样本），先确保有价值的近期事实已沉淀到长期记忆，再重建主会话观察干净基线；
   - 若带旧会话继续运行，复测时应记录“带历史上下文惯性”，避免把上下文惯性误判为提示词失效。
5. **24 小时后复测**：用同一口径指标对比改前/改后；若无明显改善或引入新副作用，优先回退而不是继续往上叠补丁。

| 模型标识 | 实测表现与常见漂移 | 适配建议 |
| --- | --- | --- |
